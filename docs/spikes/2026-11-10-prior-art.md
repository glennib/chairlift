## 1. Jinja handling: sqlfmt 0.32.0 (c57793a) and sqlfluff (b963e61)

Cases are in sqlfmt/cases/c1..c15 and issue JSON in sqlfmt/issues/.
I re-checked c10 and c15 myself.

- Lexing (verified). sqlfmt matches `\{[{%#]` with higher priority than quoted names, but only at the current position,
  so a string that starts before a tag swallows it.
  Issue #213 is still open and reproduces on 0.32.0: `var('d')` becomes `var(' d ')`.
  `{{ }}` ends are found with jinja2's lexer.
  `set`/`call` bodies are opaque.
- `{% if %}` (verified).
  There is no branch analysis.
  At `else`/`elif` the SQL context is reset to its state at the `if` (actions.py:434).
  That handles clause-level alternatives and unbalanced parentheses across branches without erroring.
  Short blocks get merged onto one line.
- Indentation (verified).
  Tags are indented to the surrounding SQL depth.
  The column-0 tags DESIGN.md describes come from unsupported DDL
  (e.g. CREATE MATERIALIZED VIEW): the SQL is kept verbatim but the tags are still re-indented to depth 0.
- Glued tags (verified).
  Adjacency is preserved (`events_{{ suffix }}`, `{{ ref('x') }}.col`), with one asymmetry:
  `n={{n}}+1` became `n ={{ n }}+1`.
- **c10: changes what the SQL means, and the safety check passed (verified).**
  The input is `x = 1 -- note\n{%- if y %}\n  and y = 2`.
  Output: `x = 1  -- note\n    {%- if y %} and y = 2`.
  Because `{%-` strips the preceding newline, the rendered output puts `and y = 2` inside the comment.
- **c15: produces invalid Jinja, and the safety check passed (verified).**
  `{%+ if x %}` became `{% + if x %}`; jinja2 rejects it with "tag name expected".
- Safety check (verified, api.py:333-385).
  It compares token types only, ignoring NEWLINE and COMMENT.
  Comments are compared with whitespace removed.
  Token values and tag text are never compared.
  It is skipped under `--fast`, `--check` and `--diff`.
- jinjafmt (verified).
  Tag contents go through black whenever black is importable (opt-out with `--no-jinjafmt`).
  Even with it off, tag padding is normalised (`{{n}}` becomes `{{ n }}`).
  Issues #155, #156, #177 and #182 are black producing invalid Jinja.
- Other issue themes (gh, tconbeer/sqlfmt):
  - Unstable multiline-tag indentation: #138, #175, #176, #600.
  - Code ending up commented out: #554, #628.
  - Unsupported Jinja syntax: `for…else` (#549), `call` (#335, #338, #353).
  - Unsupported DDL with a tag on the same line: #700.
  - Request to indent blocks: #403.
- sqlfluff (verified).
  Literals are replaced with breadcrumbs, the template is rendered,
  and the breadcrumbs that come out show which path was taken (slicers/tracer.py).
  Unreached branches are forced to True/False, giving up to 5 variants (`render_variant_limit`).
  Fixes are applied only to literal slices.
  This yields real rendered SQL for every branch, but costs template execution,
  several renders and about 2,400 lines of slicing code.

Rules worth adopting:

1. Lex Jinja before SQL quoting.
2. Find tag ends with a scanner that knows Jinja strings and nested braces.
3. Accept `{%-`, `{%+`, `-%}` and `+%}`, and never touch the bytes of a tag, padding included.
4. Keep glued/spaced adjacency on both sides of every tag.
5. At `else`/`elif`, reset the SQL context to its state at `if`.
6. Indent a tag to its SQL depth, but leave tags alone inside verbatim regions.
7. Treat whitespace next to a stripping marker as fixed.
   Never join a `--` line with what follows.
8. Make the token check compare values and tag text byte for byte, and run it in `--check`/`--diff` too.
9. Keep formatting inside tags out of scope.
10. Test idempotence on multiline tags.

## 2. ClickHouse grammar checklist: sqlglot (e3963f5, v30.30.0) and AfterShip/clickhouse-sql-parser (4536e34)

Material is in grammar/.
Syntax claims were checked with clickhouse-format 26.10 on inputs written here.

- sqlglot.
  - Tokenizer: `#` and `#!` comments, `$…$` heredocs, `0x`/`0b`/`1_000`, identifiers that start with a digit,
    `.:` and `.^`.
  - Parser: SETTINGS/FORMAT/PREWHERE/SAMPLE/QUALIFY, joins ANY/ALL/ASOF/ARRAY/PASTE/GLOBAL, INDEX/CODEC/PROJECTION,
    ENGINE/REFRESH, `{x:Type}`, `?:`.
  - Kept as unparsed `exp.Command`: CREATE USER/ROLE/QUOTA/ROW POLICY/SETTINGS PROFILE, SYSTEM, EXPLAIN, SHOW, RENAME,
    OPTIMIZE, EXCHANGE, ALTER MATERIALIZE/UPDATE/ATTACH/DETACH/FREEZE/MOVE PARTITION, `MODIFY … REMOVE`,
    and a REFRESH with no EVERY/AFTER.
  - Comments are attached to AST nodes.
    From memory: they are re-emitted as `/* */`.
- AfterShip.
  - Any statement not in parseStmt (parser/parser_table.go:1673) is a hard error; there is no passthrough.
  - The lexer throws comments away (lexer.go:311).
  - It has no `#` comments and no heredocs, and non-ASCII outside quotes is an error.
  - Nodes carry byte positions.
    Its beautifier loses comments.
  - Missing: PASTE JOIN, QUALIFY, `CREATE TABLE … EMPTY AS`, EPHEMERAL, ALTER MOVE PARTITION, ALTER USER, REVOKE,
    SETTINGS PROFILE/QUOTA.
  - EXPLAIN is partial.
- Lexical traps a generic SQL lexer gets wrong (all checked with CH):
  - `#` and `#!` comments, and nested `/* /* */ */` comments.
  - `\` escapes as well as `''` in strings, and both doubled-quote and backslash escapes in `` ` `` and `"` identifiers.
  - `$$…$$` and `$tag$…$tag$` strings, `x'41'` and `b'01'`.
  - Numbers: `0x1F`, `0b101`, `1_000`, `1.`, `.5`, `inf`, `nan`.
  - `t.1` (and `t.1.2`) is tuple access, not a float.
  - `1abc` is an identifier, and `{name:Type}` is a query parameter.
  - Operators `::`, `->`, `<=>`, `==`, `.:`, `.^`.
  - Adjacent string literals are a syntax error.
    `-1::Int8` casts the text `'-1'`.
- Grammar points from the checklist:
  - CH accepts a map literal only as a SETTINGS value.
  - FINAL must come before PREWHERE.
  - LIMIT … WITH TIES requires ORDER BY.
  - `LEFT ANTI` and `ANTI LEFT` are both accepted.
  - A TTL or SETTING list swallows the next ALTER command after a comma.
  - 26.10 rejects CREATE LIVE VIEW and CREATE WINDOW VIEW.
- clickhouse-format can't serve as a round-trip normaliser.
  It reorders clauses (COMMENT/CODEC, LIFETIME/LAYOUT), drops passwords, rewrites `||`, `?:`, `::` and INTERVAL,
  and refuses JSONEachRow inline data.
  It is still useful as a validity oracle.

The combined feature table has about 45 rows; it is reproduced in the hand-back message.

## 4. Safety and verification in other formatters (verified in source)

- Black (src/black/**init**.py:1229, parsing.py):
  - Checks AST equivalence (assert_equivalent) and then stability (assert_stable, a second format pass) before writing.
  - The AST dump is normalised: docstring whitespace is stripped per line, type_comment is rstripped.
  - `--fast` skips the check.
    A failure is reported as "INTERNAL ERROR … produced different code on the second pass", with a dump file.
- ruff:
  - The `ruff format` CLI (crates/ruff/src/commands/format.rs) runs no AST or stability check.
  - The checks live in tests: `ensure_stability_when_formatting_twice` and `ensure_unchanged_ast`,
    which uses a Normalizer and then ComparableMod (ruff_python_formatter/tests/fixtures.rs:378, 442).
  - They also run in the corpus tool `ruff_dev format-dev --stability-check`,
    which reports SyntaxErrorInOutput and Unstable and flags any file over 50 ms (format_dev.rs:820-870).
- Prettier:
  - Each comment gets precedingNode, followingNode and enclosingNode, and is classed ownLine, endOfLine or remaining.
    It becomes leading on the following node, else trailing on the preceding node, else dangling on the enclosing node,
    with per-language override hooks (src/main/comments/attach.js).
  - ensureAllCommentsPrinted throws "Comment … was not printed.
    Please report this error!" (comments/print.js:277, ast-to-doc.js:54).
    That assertion is cheap and worth copying.
  - Errors in embedded languages are swallowed and the source kept unless PRETTIER_DEBUG is set (multiparser.js:48).
- StyLua:
  - `--verify` is opt-in.
    It reparses the output and compares the ASTs after massaging away the changes the formatter makes,
    such as parentheses and quote style (src/verify_ast.rs, src/cli/opt.rs:52).
- What follows for chairlift:
  - The planned token-stream check is stricter than any of these and cheaper than Black's.
  - Add three things: a stability pass in tests and in a corpus tool
    (as ruff does),
    a "every comment and Jinja tag was emitted" assertion
    (as Prettier does), and checks that also run under `--check`/`--diff` (unlike sqlfmt).

- The patterns that matter:
  - `{{ config(…) }}` blocks spread over several lines at the top of the file.

  - Tags used as a table (`FROM {{ source(…) }} final`).

    as SQL strings with `\'` escapes. chairlift must leave those strings alone.
